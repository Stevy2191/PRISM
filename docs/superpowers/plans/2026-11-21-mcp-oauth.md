# Claude connects with OAuth (MCP-O) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** claude.ai (and any MCP client) adds `https://<PUBLIC_APP_URL>/mcp` as a connector; each person signs in to PRISM, approves, and Claude acts as them, off until an Owner enables it.

**Architecture:** The backend becomes an OAuth 2.1 authorization server (DCR + CIMD, PKCE S256, opaque SHA-256-hashed tokens) and hosts `/mcp`, running the shared tools from `mcp/src/tools.js`. The tools call `/api/v1` over an internal loopback listener with a per-request in-memory grant, so the OAuth token never reaches the API.

**Tech Stack:** Express 4, Sequelize 6 / MariaDB, `@modelcontextprotocol/sdk` 1.32 (backend dependency), React 18 + React Router 7, Jest + supertest, Playwright smoke.

**Spec:** `docs/superpowers/specs/2026-11-21-mcp-oauth-design.md`

## Global Constraints

- Feature flag `mcp.enabled` default `'false'`; `mcp.allowWrites` default `'false'`; `mcp.allowedDomains` default `'claude.ai,claude.com,localhost,127.0.0.1'`.
- Issuer = `publicBaseUrl()` (`PUBLIC_APP_URL`, trailing slash trimmed); resource = `${issuer}/mcp`; scope `prism`.
- Access token `prism_oat_` + 64 hex, 1 h; refresh `prism_ort_` + 64 hex, 30 days, rotated; codes 10 min, single use; pending consent requests 10 min.
- Tokens, codes and refresh tokens stored only as SHA-256 hex.
- Admin endpoints: `settings.manage_system` + `requireOwner('Claude connections')`.
- When disabled: well-known, `/api/v1/oauth/*` (except admin) and `/mcp` answer 404.
- Errors from the token/register endpoints use OAuth JSON (`{ error, error_description }`), not PRISM's error shape.

## Review Focus

1. A refresh token used twice (stolen copy) → the whole connection is revoked; both copies stop working. *(Task 3 test `refresh reuse revokes`.)*
2. The user is deactivated, or the admin turns the feature off, after connecting → the next `/mcp` call gets 401/404, and refresh fails. *(Task 5 tests.)*
3. `redirect_uri` on authorize differs from the one registered (or from the one on the token request) → PRISM shows an error, never redirects. *(Task 3.)*
4. An OAuth access token sent to `/api/v1/...` as `Authorization: Bearer` or `X-API-Key` → 401. *(Task 5 `token never opens the API`.)*
5. CIMD `client_id` on a host not in the allowed domains, or `http://`, or the doc's `client_id` ≠ its URL → refused before/without fetching. *(Task 2.)*
